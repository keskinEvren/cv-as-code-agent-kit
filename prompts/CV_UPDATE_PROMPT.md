## Rules

1. Read `AGENTS.md` first.
2. Treat `data/resume.master.json` as the canonical source.
3. Do not invent missing dates, technologies, metrics or achievements.
4. If something is ambiguous, add it to a TODO instead of guessing.
5. Preserve stable IDs for existing records.
6. Create stable kebab-case IDs for new records.
7. Update role variants only when the new item is relevant.
8. Do not duplicate factual text in `variants.json`.
9. Respect visibility/privacy fields.
10. Run schema validation, tests, typecheck and PDF checks afterward.
11. Tell me exactly what changed.
